# Dashboard API

> **The Dashboard API provides the summarized financial data required for the application's home screen.**

---

# Purpose

This document defines the API endpoints responsible for supplying dashboard data.

The Dashboard API aggregates information from multiple sources and returns a concise overview of the user's current financial status.

All endpoints follow the standards defined in **API-Overview.md**.

---

# Base Endpoint

```text
/api/v1/dashboard
```

---

# Responsibilities

The Dashboard API is responsible for providing:

* Financial summary
* Budget overview
* Recent transactions
* Spending insights

The Dashboard API is read-only.

---

# Endpoints

| Method | Endpoint                         | Purpose                          |
| ------ | -------------------------------- | -------------------------------- |
| GET    | `/dashboard`                     | Retrieve complete dashboard data |
| GET    | `/dashboard/summary`             | Retrieve summary metrics         |
| GET    | `/dashboard/recent-transactions` | Retrieve recent transactions     |
| GET    | `/dashboard/insights`            | Retrieve dashboard insights      |

---

# Dashboard Summary

Returns key financial metrics for the selected period.

Typical values include:

* Total Income
* Total Expenses
* Net Savings
* Budget Remaining

The selected period defaults to the current month.

---

# Recent Transactions

Returns the most recent transactions.

Default:

* 10 transactions
* Sorted by date (descending)

Each transaction should include only the fields required for dashboard display.

---

# Dashboard Insights

Returns concise financial insights generated from existing transaction data.

Examples:

* Highest spending category
* Budget nearing limit
* Increased spending compared to last month

Insights should be generated by the Service Layer.

---

# Query Parameters

| Parameter | Required | Description            |
| --------- | -------- | ---------------------- |
| month     | No       | Target month (YYYY-MM) |

If no month is provided, the current month is used.

---

# Response Behavior

Successful responses follow the standard response format defined in **API-Overview.md**.

The complete dashboard should be returned in a single response where practical to minimize client requests.

---

# Validation

Incoming requests should validate:

* Month format
* Supported date range

Invalid requests should return the appropriate validation error.

---

# Performance Expectations

The Dashboard API should:

* Load quickly for typical datasets.
* Minimize database queries.
* Reuse shared business logic where possible.
* Support responsive dashboard rendering.

---

# Error Scenarios

Common errors include:

| Status | Scenario                |
| ------ | ----------------------- |
| 400    | Invalid query parameter |
| 422    | Validation failed       |
| 500    | Unexpected server error |

---

# Relationship to Other Features

The Dashboard API consumes data from:

* Transactions
* Budgets

It presents aggregated information without exposing business logic directly through the API.

---

# Testing

Testing should verify:

* Summary calculations
* Recent transaction retrieval
* Insight generation
* Month filtering
* Error handling

---

# Acceptance Criteria

The Dashboard API is complete when:

* Dashboard summary is returned correctly.
* Recent transactions are ordered correctly.
* Insights are generated consistently.
* Responses follow the standard API format.
* Validation and error handling are implemented.

---

# Goal

The Dashboard API should provide a fast, reliable overview of the user's financial activity while minimizing the number of requests required by the frontend.
